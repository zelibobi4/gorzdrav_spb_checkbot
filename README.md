# Gorzdrav SPB Checkbot — расширенный форк

Telegram-бот для мониторинга свободных талонов на [gorzdrav.spb.ru](https://gorzdrav.spb.ru/) с уведомлениями в Telegram.

Это расширенный форк проекта [cucumberian/gorzdrav_spb_checkbot](https://github.com/cucumberian/gorzdrav_spb_checkbot). В этой версии основной упор сделан на более точный поиск подходящего времени и мониторинг сразу всех врачей выбранной специальности.

## Что добавлено в этом форке

- **Фильтр по времени приёма**
  - `/evening` — искать талоны с 17:00 до конца дня;
  - `/time 18:00-23:00` — произвольный диапазон;
  - `/time_off` — убрать ограничение по времени.
- **Режим «любой врач этой специальности»**
  - выбирается после поликлиники и специальности;
  - бот проверяет реальный список `appointments` каждого врача;
  - удобно для стоматологов и других специальностей с большим количеством врачей.
- **Совместная фильтрация по дате и времени** — например, ближайшие 15 дней и только 18:00–23:00.
- **Автоматическая миграция существующей SQLite-базы** без удаления старых пользователей и настроек.
- **Уведомление содержит конкретного врача, дату, время, кабинет и ссылку на запись**.
- **Мониторинг не отключается после первого найденного талона**: бот продолжает следить дальше.
- **Антиспам по снимку текущих талонов**: повторно тот же набор не отправляется; новое сообщение приходит только при появлении нового подходящего талона.
- В новом сообщении показывается актуальный список доступных талонов; уже исчезнувшие записи из него удаляются.
- Снимок хранится в SQLite и переживает перезапуск контейнера/VPS.
- Если подходящих талонов нет, мониторинг остаётся включённым и продолжает ждать.
- Ошибка API у одного врача не останавливает проверку остальных врачей и не считается исчезновением его талонов.

> Важная особенность API Горздрава: `freeParticipantCount` не всегда совпадает с фактически доступными `appointments`. Поэтому при активных фильтрах и в режиме «любой врач» бот проверяет реальные записи, а не только общий счётчик.

## Как работает мониторинг

1. Пользователь выбирает район → поликлинику → специальность.
2. Можно выбрать конкретного врача или **«👥 Любой врач этой специальности»**.
3. При необходимости задаётся горизонт поиска: например `/15`.
4. При необходимости задаётся время: например `/time 18:00-23:00`.
5. Команда `/on` включает мониторинг.
6. Пока подходящих записей нет, бот молчит и продолжает проверять.
7. При первом подходящем результате бот отправляет актуальный список талонов и **продолжает мониторинг**.
8. Если набор не изменился, новых сообщений нет. Когда появляется новый талон, бот снова присылает весь актуальный список подходящих талонов.
9. Если прежний талон исчез, он удаляется из внутреннего снимка и больше не показывается в следующих уведомлениях.

## Команды

| Команда | Описание |
|---|---|
| `/set_doctor` | выбрать район, поликлинику, специальность и врача либо режим «любой врач» |
| `/status` | показать текущую цель мониторинга и фильтры |
| `/on` | включить мониторинг |
| `/off` | отключить мониторинг |
| `/N` | искать в пределах N дней, например `/15` |
| `/evening` | искать только с 17:00 до конца дня |
| `/time 18:00-23:00` | задать произвольный диапазон времени |
| `/time_off` | отключить фильтр времени |
| `/help` | показать помощь |
| `/start` | создать профиль пользователя |
| `/delete` | удалить профиль пользователя |

## Быстрый запуск через Docker Compose

### 1. Клонирование

```bash
git clone https://github.com/zelibobi4/gorzdrav_spb_checkbot.git
cd gorzdrav_spb_checkbot
```

### 2. Настройка окружения

Создайте `.env` в корне проекта:

```env
BOT_TOKEN=YOUR_TELEGRAM_BOT_TOKEN
CHECKER_TIMEOUT_SECS=60
```

Стандартный `docker-compose.yml` хранит SQLite в `./data/`, поэтому база переживает пересоздание контейнера.

### 3. Запуск

```bash
docker compose up -d --build
```

Логи:

```bash
docker compose logs -f
```

Остановка:

```bash
docker compose down
```

## Запуск без Docker

Требуется Python 3.12.

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r src/requirements.txt
```

Создайте `.env`:

```env
BOT_TOKEN=YOUR_TELEGRAM_BOT_TOKEN
DB_FILE=sqlite.db
CHECKER_TIMEOUT_SECS=60
```

Запуск:

```bash
python src/app.py
```

## База данных

Используется SQLite.

Для пользователя сохраняются, в частности:

- Telegram ID;
- включён ли мониторинг;
- выбранный конкретный врач либо режим специальности;
- поликлиника и специальность;
- ограничение по дням;
- диапазон времени;
- время последней активности.

При обновлении старой базы необходимые поля добавляются автоматически.

## API

Проект использует публично доступные HTTP-эндпоинты Горздрава Санкт-Петербурга.

Полезная сторонняя документация API:
[egorantonov/gorzdrav wiki](https://github.com/egorantonov/gorzdrav/wiki/SPB-Gorzdrav-API-Documentation)

Примеры:

```text
/_api/api/v2/shared/districts
/_api/api/v2/shared/district/{districtId}/lpus
/_api/api/v2/schedule/lpu/{lpuId}/specialties
/_api/api/v2/schedule/lpu/{lpuId}/speciality/{specialtyId}/doctors
/_api/api/v2/schedule/lpu/{lpuId}/doctor/{doctorId}/appointments
```

## Производительность режима «любой врач»

В этом режиме бот запрашивает реальные `appointments` для каждого врача выбранной специальности. Если врачей много, один цикл проверки занимает заметно больше времени, чем мониторинг одного врача.

Это сознательный компромисс в пользу точности: счётчики API Горздрава могут показывать 0 свободных мест даже тогда, когда endpoint `appointments` возвращает доступные записи.
